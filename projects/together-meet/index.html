Together Meet

Together Meet is a small calling application for two participants. Joining through a room link is simple; the engineering work is in negotiation, device permission, participant state, and cleanup when the connection changes.

My role
Personal project
Project scope
Browser application with public base source; private Android extension

On this page

  1. Separate signaling from the media path
  2. The room has an explicit limit
  3. Leaving is as important as joining
  4. Android adds a second lifecycle

Technology

  • React
  • TypeScript
  • WebRTC
  • Socket.IO

Separate signaling from the media path

Socket.IO manages room membership and relays offers, answers, and ICE candidates. WebRTC carries audio and video between peers. Configurable STUN/TURN support addresses connectivity across different networks.

The distinction matters when investigating a failure. A connected signaling socket does not prove that media is flowing, and a visible participant does not prove that the browser has permission to use a device. The interface includes feedback and diagnostics for these separate states.

The room has an explicit limit

The signaling policy permits two participants. A joining client must handle waiting for a peer, an admitted remote participant, and a rejected attempt to enter a full room. The client also handles missing devices and permission errors.

Tests in the project cover room admission and signaling behavior, including isolation between rooms. Client checks cover joining and media cleanup. These are useful, bounded guarantees rather than a claim that every camera, browser, and network combination has been exercised.

Leaving is as important as joining

Media tracks and peer state need to be cleared when a peer leaves or admission fails. Otherwise an interface can look active while it holds stale state, or continue using a device after the user expects the session to have ended.

That makes cleanup part of the call lifecycle, not just a component-unmount detail. The project is small enough to trace the path from membership events through client state to media teardown.

Android adds a second lifecycle

The newer companion work adds private ringing links and incoming-call notifications on Android. A restricted WebView hosts the meeting while native code handles notification behavior.

That extension creates device-lifecycle questions beyond the browser implementation. Physical-device ringing remains a separate validation step. The public client and signaling repositories document the base application; they should not be mistaken for the complete private Android extension.

Project notes

Two-person personal application; no recording or verified caller identity. Physical Android ringing has not been verified. Current public service availability is not certified by this source review.
