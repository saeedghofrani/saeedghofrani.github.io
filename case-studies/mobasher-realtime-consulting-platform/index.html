Mobasher: microservices behind messaging and consultation

Mobasher combines consulting and learning with communication. I developed backend services in a NestJS microservice architecture, integrated communication workflows with the Angular application, and worked on SQL retrieval paths for frequently used screens.

My role
Backend Engineer (Freelance) · 2023–2025

Client-owned production platform · private source

Result and scope

500+ concurrent production users with observed messaging latency of 100–150 ms.

Services around a consultation

Mobasher brings together provider information, reservations, learning workflows, and live communication. I developed backend services in its NestJS microservice architecture and integrated communication workflows with the Angular application.

The service boundaries matter when a user moves from choosing a provider to arranging a session and communicating. Provider and reservation data, messages, and call state each have a different responsibility within that journey.

Messaging and media follow different paths

WebRTC handles voice and video media. Socket.IO supports application events, while RabbitMQ participates in backend communication workflows. I developed the associated NestJS services and integrated these interactions with Angular.

A socket connection, a consultation record, and a media stream describe different parts of a session. Keeping those responsibilities distinct makes it possible to discuss messaging responsiveness without confusing it with call quality.

Improving the surrounding data paths

I improved SQL stored procedures and retrieval paths for frequently used screens. Provider, reservation, and history screens are part of the same experience as messaging, so the database work supported the steps before and after a consultation.

Production observation

The application supported more than 500 concurrent production users, with observed messaging latency of 100–150 milliseconds. A separate load test observed approximately 30 milliseconds.

The production figure describes messaging responsiveness. Voice/video latency and the separate load-test conditions are different measurements.

Project notes

Freelance contribution, 2023–2025; client source and user data are private. Concurrency and latency are my reported observations, without a percentile or voice/video latency claim.
