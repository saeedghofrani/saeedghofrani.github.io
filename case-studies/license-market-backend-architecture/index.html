LicenseMarket: faster APIs, dependable operations, and a backend team

At LicenseMarket, I work on a commerce and CRM platform used by customers, operators, and accounting colleagues. My role combines implementation and production support with managing a backend team of eight. The work spans the everyday paths that make an operating business function: orders, tickets, wallet transactions, refunds, reporting, and communication.

My role
Engineering Manager / Backend Engineer · 2023–present; management since early 2024
Project scope
Employer-owned production system · private source

Result and scope

40% lower average API latency and 99.9% availability over approximately six months; management of eight backend engineers.

Making daily CRM work faster

At LicenseMarket, customers place orders while operators handle tickets and accounting colleagues investigate transactions. I work across those connected paths in NestJS, with PostgreSQL and Prisma for persistence, Redis for caching, and RabbitMQ for background work.

I improved database and API read paths by bounding queries, selecting the fields a screen needs, working on indexes, and caching repeated reads. Preserving filters, permissions, ordering, and response shape mattered: a faster response still had to behave correctly for the existing application.

Database and API timing tests over approximately six months showed a 40% reduction in average API latency. The work covered several changes across the request path; the result measures average API response time rather than a percentile for every endpoint.

Keeping financial operations explainable

I worked with accounting colleagues on refund workflows, wallet transactions, and reports. A balance change needs to remain understandable both on the operator screen and in the report used to reconcile it later.

That work connects API behavior to the records behind an operation: the action taken, the actor involved, and the filters used to retrieve it. I also contribute to ticketing, document automation, and AI-assisted chat workflows.

Operating the services after release

My production responsibilities include Kubernetes, Grafana monitoring, database administration, and Bash and PowerShell automation. UptimeRobot, application monitoring, and the CRM incident panel provide the records used to investigate availability.

Platform availability was 99.9% over approximately six months. I also worked on VoIP servers and a Mattermost plugin involving message and channel access, search behavior, and responsiveness.

Making delivery easier to follow

I began managing backend engineers in early 2024 and now lead eight engineers. My responsibilities include hiring, one-to-ones, performance reviews, mentoring, and delivery planning alongside implementation and code review.

I introduced GitHub Projects and issues to organize delivery, supported by pull-request review and CI/CD. After these changes, we had fewer missed tasks and incomplete features, clearer bug reports, better time management, faster delivery, and fewer bugs reaching releases.

I mentor through hands-on project work: discussing a change, reviewing its data model or service boundary, and working through the implementation with the engineer. The role has also included coordinating more than five major releases.

Project notes

Shared employer-owned system; source and operational records are private. Latency and availability figures are my reported results over approximately six months, supported by timing tests, UptimeRobot, monitoring, and CRM incident records. Delivery improvements are qualitative observations.
